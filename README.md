# 旅行ポータル

管理者がPCやスマホから入力した **お知らせ・チーム発表・ポイント** を、参加者がそれぞれのアカウントでスマホから見られる Web アプリです。

- 画面：GitHub Pages（無料）
- ログインとデータ保存：Firebase（Authentication + Cloud Firestore、無料の Spark プランで足ります）

## できること

| 機能 | 管理者（admin1〜admin3。画面では「管理者1〜3」） | 参加者（user01〜） |
|---|---|---|
| お知らせ | 投稿・削除・固定。宛先を **全員 / 特定チーム / 特定の人 / 人ごと** から選べる。画像は3枚まで（自動で縮小）。**人ごと**：タイトルと本文は同じで、**1人ずつ別の内容（暗証番号など）** を一斉に送る。内容は手で入れるほか、**ランダムな数字（4〜8桁・重ならない）**・**参加者の情報の項目**・**Excel などからの貼り付け（ID か名前、タブかカンマ、内容）** で入れられる。だれに何を送ったかは管理者だけが見られる。通知には人ごとの内容を入れない | 自分が見てよいものだけ表示。人ごとのお知らせは「あなただけに届いた内容」を大きく表示（コピーできる） |
| 参加者の情報 | 「参加者」の画面で、**住所・大学・学年・電話番号・誕生日など** の項目を自由に作り（1行・複数行・選択肢・日付。よく使う項目はボタン1つで追加）、名前の横の「情報」から1人ずつ入れる。**同じ ID の人なら全部の旅行で共通**。一覧で見られ、**CSV（Excel で開ける）** で保存できる。チームの画面の「参加者の属性」（チーム分け用・旅行ごと）とは別 | **見えない（本人の分も）** |
| チーム | **チーム表を複数**作れる（例：チーム表1＝競技、チーム表2＝料理班）。チーム表ごとに作成・振り分け（手動 / ランダム）・**発表**。チームごとに **👑リーダー** を選べる（表示だけ）。振り分けの欄で、1人ずつ **役職を手入力**できる（空欄なら役職なし。チーム表ごと）。チーム一覧にはメンバーを1人ずつ箇条書きで表示。**参加者の属性**（性別・学年など項目は自由に作れる。選択肢つき／自由記入）を管理者だけが入力でき、チームごとの内訳表示と「○○で均等」なランダム振り分けに使える | 発表されたチーム表だけ見える |
| ポイント | 個人用・チーム用を付与・取り消し。1件ごとに **全員に公開 / チーム内のみ / 本人のみ** を選べる | 自分・自分のチーム・公開ランキング。加点・減点はお知らせ欄にも緑 / 赤で流れる |
| ポイントQR | 「ポイント」の下の「ポイントQR」で、名前・もらえるポイント・**受け取れる回数（全体で1回だけ／先着○人／1人1回ずつ）**・入る先（読んだ人の個人ポイント／読んだ人のチーム）を決めて作る。**大きさ（3・5・8・15cm）を選んで印刷**。受け取った人の一覧、停止・再開、削除 | スマホのカメラで読み取るとアプリが開き、ポイントが入る（ログイン前ならログイン後に受け取る）。もう受け取った・人数に達した・停止中のときはその旨を表示 |
| ポイント交換 | 個人間・チーム間で「渡す側 −N / 受け取る側 +N」を1組で登録。取り消すと両方戻る | 自分に関係する交換がお知らせ欄に流れる |
| 見ました | お知らせに「見ました」ボタンを付けられる。見た人 / まだの人がわかる | ボタンを押すだけ |
| スパイ | チーム表ごとに「参加先チーム」と「本当のチーム」を登録。チームへのポイントは「誰の功績か」を選べ、スパイの功績は参加先 / 本当のチームのどちらに加算するか選べる | 他の人からは参加先の普通のメンバーに見える。本人にだけ本当のチームが見える |
| 表・メモ | 「全体公開」と「管理者用」の2つの欄に、メモと表（リーグ戦の星取表など）を自由に追加・編集。「〜へ移す」で欄を移せる | 公開された表・メモを見られる |
| 地図 | 右上（スマホは左上）の地図ボタンで現在地を表示。「設定」で参加者への表示をオン / オフ。「参加者の位置を共有」をオンにすると、全員の位置が名前つきで地図に出る（「参加者同士でも見られる」で参加者にも表示）。オフのときも、**「位置の共有グループ」**（管理者が設定で作り、メンバーを選ぶ）の中ではお互いの位置が見える | 管理者がオンにすると地図ボタンが出る。一度見た範囲の地図は電波がなくても表示できる |
| クイズ | 「クイズ」から問題（4択 / 記述 / 早押し / **並べ替え** / **投票当て**）・配点・制限時間・解答者を登録。**表示用**（プロジェクター用、admin1 など）と**操作用**（admin2 など）の画面を別アカウントで開き、出題 → 締切 → 正誤判定 → 発表を操作。発表は「一斉 / 一人ずつ」「回答だけ先に見せる → ○× 」など、その場で選べる。終了時に得点をポイントに反映できる。クイズの終了は **2回押して確定**（「クイズ」の一覧の「クイズを終了する」からも終了できる）。操作用の画面には**次の問題**も表示。**問題読み**（問題文を1文字ずつ出す画面）を問題ごとに入れられ、早押しは最初から入っている（読み上げ中も押せて、押された所で止まる）。早押しの誤答・時間切れは表示用の画面の「誤答」一覧にすぐ出る | 解答者に選ばれた人のスマホに解答画面が自動で出る。問題文をスマホにも出すかは問題ごとに管理者が決める。早押しは「問題が届いてから押すまでの時間」で順位を付けるので、通信の速さの差は影響しない。押した順に解答権が回り、解答権を得たら6秒以内に答えを入力（間に合わなければ誤答）。並べ替え・順位当ては項目をタップした順に番号が付き、そろったら送信 |
| 並べ替え・投票当て | **並べ替え**：項目（2〜8個）を正しい順で登録すると、スマホにはバラバラに出る。**投票当て**：事前の **アンケートの結果が正解**になる問題。「1位を当てる」か「上位N位（2〜5）の順番を当てる」を選ぶ。同じ票数のものはどちらを選んでも正解。順位投票のアンケートを使うと、合計点の順位が正解になる。並べ替え・順番当ては **部分点**（合っている位置の数 ÷ 全体 × 配点、切り捨て）をオンにできる。表示用の画面では、発表で正しい順番や **票数の棒グラフ**が出る | 発表後、自分の答えの各位置に ○× が付き、部分点のときは「おしい！ 2/4」と出る |
| クイズの妨害・賭け | クイズごとに **妨害システム** と **順位予想（賭け）** をオン・オフ。使うポイントは「個人」か「チーム（チーム表を選ぶ）」。妨害は 封印・時間短縮・目隠し（標準）＋ 出遅れ・シャッフル・逆さま（4択・記述向け、オフで用意）を種類ごとにオン・オフ・値段設定。クイズを **区切り（A問題・B問題…）** に分け、区切りごとに「1人が妨害できる回数」「1人が受ける種類ごとの上限」を決める。賭けは 単勝・2連単・3連単・3連複（パリミュチュエル方式、払戻率・上限を設定）。開始前に **ルール説明スライド** を表示用の画面とスマホに出せる | 解答者以外（設定で全員も可）が、操作用の画面の「妨害受付」中にスマホから相手と種類を選んで申し込む。次の問題が出た瞬間に先着順で確定（1問で1人が受ける妨害は1つまで・失敗はポイントを引かない・同じ人を2問続けて狙うと2倍）。誰が誰を妨害したかは画面に出る。賭けは受付中にオッズを見ながら賭け、結果発表で払い戻し（誰も当たらなければ返金） |
| 地図のピン | 地図の「📍ピン」を押してから地図をタップすると、そこにピンを刺せる（名前・メモ・アイコン・色・「全員に表示 / 管理者だけ」）。ドラッグで移動、タップで編集・削除 | 「全員に表示」のピンだけ見える。タップで名前とメモ |
| 出欠・集金 | 「出欠・集金」から **アンケート**（選択肢・**選択肢を参加者の名前にする**・締切・集計を参加者に見せるか・コメント欄・**誰が何に入れたかを出さない**・**順位をつけて投票する**（「優しいと思う順」など。選択肢にする人をアカウントから選べ、「自分には投票できない」「何位まで付けるか」も設定可。1位＝多い点…の合計点で集計）・答えてもらう人＝全員 / アカウントから選ぶ）を作り、回答状況と未回答の人を確認。回答を代わりに入れることもできる。**集金**（名前・1人あたりの金額・期限・振込先などのメモ・対象＝全員 / アカウントから選ぶ / アンケートで「参加」と答えた人など）を作り、1人ずつ **未入金 / 入金済み / 免除**・払い方（現金・振込・PayPay）・金額の個別変更を付ける。人ごとの未入金の合計も表示。アンケート・集金とも、**作ったあとで「対象者を変える・追加する」から対象者を足したり外したりできる** | アンケートに回答（締切まで変更可）。順位投票は、選択肢をタップした順に1位・2位…が付き「この順で投票」。自分の集金の金額と入金状況が見える。払ったら **「送金しました」** を押して報告（払い方・メモ・スクリーンショットは任意）。管理者の画面に「確認待ち」として出て、管理者が「入金済みにする」を押すと確定する。未回答・未入金があると上に表示される。**受付中のアンケートと、期限内（どの状態でも）・期限後で未入金（確認待ちを含む）の集金は、お知らせより上（ページの一番上）に表示**（期限なしの集金は未入金のときだけ） |
| 立て替えの精算 | 「出欠・集金」→「立て替え」で、誰が立て替えたか・金額・割る人（全員 / アカウントから選ぶ）を登録（参加者の代わりにも登録できる）。**支払いの回数が最少に近くなる精算表**（最大でも人数−1回）と、人ごとの差し引きを表示。「払った」で精算を記録 | 自分が立て替えた分を登録。「あなたの精算」に誰にいくら払う / 受け取るかが出て、払ったら「払った」を押す。1円の端数は割る人の先頭から1円ずつ多く負担 |
| チェックリスト | 「チェック」から **セクション**（持ち物・片付け・出発前など）をいくつでも作り、項目を追加・並べ替え・削除。項目は **各自**（全員がそれぞれチェック。まだの人がわかる）か **共有**（誰か1人がやればよい。担当者を決めることもできる） | 自分がやる項目の進み具合（例 3/5）とチェック欄。共有の項目は誰がチェックしたかが出る（他の人がチェックしたものは外せない） |
| チャット | 「チャット」から **全体チャット・各チームのチャット・各参加者との1対1（管理者への連絡）** に書き込める。参加者どうしの **DM もすべて見られる**（閲覧のみ）。メッセージの削除もできる | 全体チャット、自分のチーム内チャット、「管理者への連絡」、参加者どうしの DM（「新しいDM」から相手を選ぶ）。**写真も送れる**（端末で縮小。開いたチャットの写真だけ読み込む）。未読の数がチャットのボタンに出る |
| 確定前ページ | 「設定」→「確定前ページを作る」で作成（そのとき今の参加者は全員「未確定」で登録される）。お知らせ・出欠／アンケート・集金・チャット・立て替え・参加者の管理と、**旅行の割り当て**（1人に何個でも。確定後の追加・取り消しも可）。旅行ごとの「確定する」で、割り当てた未確定の人が一斉に旅行のページへ。確定前ページの集金・出欠・お知らせは、**対象者が確定すると旅行のページにも自動で出る**（管理者も旅行のページで入金の記録や送金報告の確認ができる。書き込みは確定前ページへ）。確定前ページがあるときは、**参加者IDの作成は確定前ページだけ**で行い、旅行の「参加者」には確定した人だけが入る（「確定していない人をこの旅行から外す」で整理できる）。旅行の「出欠・集金」→「集金」の **「確定前ページへ移す」** で、旅行で作った集金を（入金の記録・送金の報告ごと）確定前ページへ移せる | 旅行が確定するまでは確定前ページ（チーム・ポイントなし）だけが開く。確定すると自動で旅行のページに切り替わり、確定前ページのお知らせ・出欠・集金も旅行のページに表示される（回答・入金状況はそのまま） |
| 旅行（プロファイル） | 「設定」または上部の旅行名から、中身が空の新しい旅行を何個でも作成・切り替え・削除できる。参加者の ID は旅行をまたいで使い回せる（同じ ID を登録すると既存のアカウントを追加） | 複数の旅行に入っている人は、ログイン後に開く旅行を選ぶ。設定からも切り替えられる |
| 画面 | PC（横幅 1100px 以上）は **お知らせ・チーム・ポイント・表・メモ／参加者を1画面**に並べる。管理者は **左にお知らせ・チーム、右半分は1つの大きな欄**（ふだんは表・メモと参加者）。上部の「ポイント」「出欠・集金」「チェック」「チャット」「設定」を押すと **右半分がその画面に切り替わる**（「表・メモ・参加者に戻る」かもう一度押すと元に戻る。クイズ・地図は小窓）。スマホはタブ切り替え | スマホは **1ページ**にまとまり、上部のボタンで移動。右上に **所属チームと所持ポイント** を常時表示 |
| 試合の記録（フットサル） | フットサルチーム用の旅行の「チーム」の画面で **試合を作る**（チーム表のチームどうし／外部のチーム・ピリオドの名前と時間を自由に（前半・後半・延長など）・記録係と担当・公開）。記録できるのは **管理者と、試合ごとに指名した記録係**。記録係は **担当（タイマー／得点／シュート／ファウル・セットプレー／ボール保持）** を1人に何個でも割り当てられ、複数人で分担できる（登録を外すとすぐ記録できなくなる。ルールでも同じ制限）。記録できるもの：ゴール（決めた人・アシスト・オウンゴール。決めた人とアシストは **どこから（左・中央・右）とどの足で（左足・右足・頭）** も）・シュート（枠内・枠外・ブロック・ポスト。どこから・どの足で）・**試合中の PK・第2PK（蹴った人と ○×。○ にすると自動でその人のゴールになる）**・ファウル（このピリオドの **累積ファウル** を表示。5つで「次から第2PK」）・イエロー／レッドカード・CK・キックイン・FK・タイムアウト・交代。同点で終わったら **PK戦**（3人ずつ／5人ずつ→サドンデス。蹴った人と ○×、決着すると勝ったチームを表示）。どれも **押した瞬間の試合時間と、入力した時刻・入力した人** が残り、あとから直せる。**ボール保持率**は、担当がチームのボタンを **押している間** そのチームの保持として数える（時計が止まっている間は数えない）。終わった試合から **仲間内の成績（勝分負・得失点・勝点。PK戦は引き分けとして数え、PK勝ちを別に表示）** と **個人成績（得点・アシスト・シュート・ファウル・警告）** を自動で集計。PDF 出力にも入る | 公開された試合を、時計・点数・記録・ボール保持率つきでリアルタイムに見られる。記録係に指名された人は、担当の分だけ操作できる |
| ポイント機能を出さない（フットサル） | フットサルチーム用の旅行では、ポイントの画面・右上の pt・ポイントQR・PDF の「ポイント」を出さない（普通の旅行に戻すとまた出る。データは消えない） | 同じ |
| アカウント | 参加者アカウントの一括作成（パスワードは自動生成）。「参加者」→「ID・パスワードを印刷」で **配る用カード**（切り取り線・ログイン用QRコード・使い方つき、A4に10枚）と **一覧表**（管理者の控え）を印刷できる | パスワード変更（変更すると、印刷物には「本人が変更済み」と出る） |
| アカウントの切り替え | `config.js` の `ACCOUNT_SWITCH`（いまは admin1 → s0406）の管理者だけ、「設定」→「参加者アカウントに切り替える」で自分の参加者アカウントに切り替えられる。初回だけパスワードを入力し、以後は両方のログインが端末に残るので入力不要 | 切り替え中は「設定」→「管理者アカウントに戻る」で戻る |
| データの PDF 出力 | 「設定」→「データを PDF で出力」で、参加者一覧・チーム・ポイント・クイズ（問題と正解）・表・メモ・出欠・集金・立て替え・チェックリストから選んで、項目ごとに改ページした明朝体の PDF にできる（印刷画面で「PDF に保存」） | — |
| 電波が弱いとき | 入力は端末に保存され、電波が戻ると自動で送信 | 最後に受信した内容を表示し続ける |

Firebase 側のルール（`firestore.rules`）で、次のことを保証しています（`tests/rules.test.mjs` の約60項目のテストで確認。2026年10月・11月に強化）。
- 旅行に参加していない人・ログインしていない人は、データを読めない。確定前ページの人は、確定した旅行のページしか読めない
- 参加者が書けるのは、決まった形の自分の記録だけ（「見ました」・位置・アンケートの回答・入金の報告・申請・チャット・立て替え・チェック・クイズの解答と申し込み・QR の受け取り）。お知らせ・集金・アンケート・ポイント・メモ・チーム・参加者などは、uid を付けても書けない
- 締め切ったアンケート・対象外のアンケートには答えられない。QR のポイントは、その QR に決めた点数を1人1回だけ
- 発表前のチーム表・部屋割り・車割り、管理者用のメモ、非表示の動画・資料、スパイの本当のチーム、クイズの問題と正解、ほかの人の DM・入金の報告は、通信を細工しても読めない
- 参加者が書く時刻は **サーバーの時刻だけ**（端末の時計や細工した時刻で、順番や「先着」・入力時刻をごまかせない）。位置・金額・賭けの点数などは、ありえない値を書けない。クイズの答えは、その問題が「解答中」の間しか書き換えられない（正解の発表後に直せない）
- 参加者の情報（住所・大学など）は **管理者だけ** が読み書きできる（参加者は本人の分も読めない）
- 人ごとに送ったお知らせの内容（暗証番号など）は、**本人と管理者だけ** が読める（ほかの参加者は、通信を細工しても読めない）
- フットサルの試合の記録は、公開した試合だけ読める。記録係が書けるのは、**指名されている間・担当の分だけ**（タイマー係は時計とピリオド、得点係はゴール…）。チーム・時間・記録係・公開の設定は管理者だけ
- フットサルの作戦ボードは、管理者が「参加者に公開する」をオンにしたときだけ読める。参加者が動かせるのは「参加者も動かせる」がオンのときのコマの位置だけ（選手の入れ替え・設定は管理者だけ）

それでも残っている制限は「知っておくべき制限」の8〜10を見てください。

## 準備手順（初回だけ・30分ほど）

> Firebase の画面の表記は変わることがあります。見当たらないときは同じ意味の項目を探してください。

### 1. Firebase プロジェクトを作る
1. https://console.firebase.google.com/ に Google アカウントでログインする
2. 「プロジェクトを作成」を押す。名前は何でもよい（例：`nanuka-island`）。Google アナリティクスは **オフ** でよい

### 2. ログイン機能を有効にする
1. 左メニューの「構築」→「Authentication」→「始める」
2. 「ログイン方法」タブで **メール / パスワード** を有効にして保存する
3. **「ユーザー」タブ →「ユーザーを追加」で、管理者2人を作る（この手順は必ず最初に行うこと）**
   - `admin1@island.example.com`（パスワードは自分で決める）
   - `admin2@island.example.com`
   - `admin3@island.example.com`
   - アプリでは `admin1` / `admin2` / `admin3` と入力すればログインできます（画面上の名前は「管理者1」「管理者2」「管理者3」）

> ⚠️ 管理者アカウントを作る前にアプリの URL を公開すると、他人が先に `admin1` を作って管理者になれてしまいます。必ず先に作ってください。

### 3. データベースを作る
1. 「構築」→「Firestore Database」→「データベースを作成」
2. ロケーションは `asia-northeast1`（東京）または `asia-northeast2`（大阪）を選ぶ。**あとから変更できません**
3. 「本番環境モード」で開始する
4. 「ルール」タブを開き、中身を全部消して、このフォルダの `firestore.rules` の中身を貼り付け、「公開」を押す
   - **アプリを新しくしたときに `firestore.rules` も変わっていたら、同じように貼り直してください**（2026年10月の強化 = v73、フットサルの作戦ボード = v80、試合の記録とセキュリティの強化 = v81、PK・PK戦 = v82、参加者の情報・人ごとのお知らせ = v84 で変わりました）

### 4. アプリと Firebase をつなぐ
1. 歯車アイコン →「プロジェクトの設定」→ 下の方の「マイアプリ」で `</>`（ウェブ）を押す
2. アプリ名を適当に付けて登録する（Firebase Hosting は **不要**）
3. 表示された `firebaseConfig` の値を `config.js` の `productionConfig` に貼り付ける
4. 必要なら、`config.js` の `APP_TITLE` も書き換える

### 5. GitHub Pages で公開する
1. このフォルダの中身を、GitHub の **public** リポジトリのいちばん上の階層に置く
2. リポジトリの「Settings」→「Pages」→「Build and deployment」で、Source を「Deploy from a branch」、Branch を `main` / `/(root)` にして保存する
3. 1〜2分待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける
4. Firebase に戻り、「Authentication」→「設定」→「承認済みドメイン」に `<ユーザー名>.github.io` を追加する

### 6. 参加者アカウントを作る
1. `admin1` でログインし、「参加者」タブ →「まとめて作成」で `user` `1` 〜 `16` を指定して作成する
2. **表示されたパスワードの一覧を必ずコピーして保存する（あとから再表示できません）**
3. 一覧で表示名（例：たろう）を変更して「保存」を押す
4. 各自に ID とパスワードを渡す（LINE の個別メッセージなど）

### 7. 出発前に必ずやること
- [ ] 全員に一度ログインしてもらい、「ホーム画面に追加」してもらう（アプリのように開け、電波がなくても画面が出る）
- [ ] 機内モードにしてアプリを開き直し、お知らせが表示されることを確認する
- [ ] 管理者2人とも、スマホからポイントを付けられることを確認する
- [ ] チーム表と大事なお知らせは **紙でも1部** 用意する

## 当日の使い方のコツ

- **チーム発表**：「チーム」タブで振り分けを済ませてから「チームを発表する」を押すと、全員の画面に一斉に表示されます。押すまでは参加者からはまったく見えません
- **ポイントの公開範囲**
  - 全員に公開：公開ランキングに反映される
  - チーム内のみ：そのチームのメンバーだけが見られる（相手チームにはわからない）
  - 本人のみ（個人ポイントだけ）：その人だけが見られる
- **間違えたら**：「ポイント」タブの履歴にある「取消」で消せます
- **電波がないとき**：管理者が入力した内容は端末に保存され、電波が戻ったときに自動で送信されます（画面上部に「未送信の変更があります」と出ます）

## 人数・データが増えても重くならないための工夫

参加者20人・お知らせ500件・ポイント履歴3000件で計測しました（PC の Chromium、Firebase エミュレーター）。

| 項目 | 対策前 | 対策後 |
|---|---|---|
| 管理者PCの画面1回の描き直し | 約256ms | 約11ms |
| 参加者スマホの画面1回の描き直し | 約34ms | 約5ms |
| 誰かの位置が届いたときの参加者画面の固まり（10秒間の合計） | 約8.7秒 | 0秒 |
| 参加者の画面の部品数 | 約2,700 | 約600 |

- 長い一覧は最初の20〜50件だけ表示し、「さらに表示」で増やす
- 位置・クイズの更新では、地図・クイズの画面だけを描き直す
- 位置のデータは **地図を開いている間だけ** 受け取る。送る間隔は「30m 以上動いたとき（15秒以上あける）／止まっていても2分に1回」
- 参加者はお知らせ・ポイント履歴を **新しい順に一部だけ** 読み込む（「過去の分を読み込む」で追加）。合計ポイントは `stats/points` に集計して読む。集計は付与・取消のたびに更新し、管理者の端末が全履歴と照らし合わせて、ずれがあれば自動で直す
- Firebase 無料枠（読み取り 5万回/日・書き込み 2万回/日）を使い切ると、その日は（日本時間の夕方まで）アプリが動かなくなるため、読み取り・書き込みの回数を減らすことを優先した

## 知っておくべき制限（正直に書いておきます）

1. **印刷用に、作成したときの初期パスワードを Firebase の `accounts`（管理者だけが読める場所）に控えています。** 参加者からは読めないことをルールのテストで確認済みです。印刷の機能を入れる前に作ったIDは記録がないので、印刷物では空欄（手書き用）になります
1. **参加者がパスワードを忘れたとき、アプリからはリセットできません。** Firebase の無料プランでは、他人のパスワードを変更する仕組みを作れないためです。対策：
   - 管理者はパスワード一覧を必ず保管する
   - 参加者には「パスワードを変更するなら絶対に忘れないこと」と伝える
   - 最終手段：Firebase コンソールでそのユーザーを削除し、アプリで同じ ID を作り直す。**ただし、その人の個人ポイントとチームの所属は引き継がれません**（チーム所属は付け直せます）
2. **アカウントの作成は電波のある場所で行ってください**（オフラインでは作れません）
3. 画像は端末側で縮小して保存しています（1枚あたり最大約180KB、1つのお知らせに3枚まで）。地図などを細かく見せたい場合は、紙も用意してください
4. 参加者の名前は、ログインしている参加者全員から見えます（チーム発表前でも）
5. チーム表を削除しても、そのチームに付けたポイント履歴は残ります（表示は「（チーム）」になります）
6. 地図は OpenStreetMap を使っています。**電波のない島で地図を出すには、出発前に電波のある場所で島のあたりを一度表示しておく**必要があります（拡大率ごとに保存されるので、使いたい拡大率で一度見ておく）。GPS 自体は電波がなくても動きます
7. 位置の共有は、**参加者がアプリを開いている間だけ**届きます（スマホを閉じたり別のアプリを使ったりすると止まる。ブラウザの仕組み上の制限）。最後に届いてから5分以上たった人は灰色で表示されます
8. 送金報告に付けたスクリーンショットは、本人と管理者だけが読めます。それでも、口座番号や残高など見られたくない部分は写さないか、隠してから付けるよう伝えてください
9. チャットは管理者がすべて（参加者どうしの DM も）見られます。**画面には表示しないので、事前に管理者から参加者へ口頭で伝えてください**。DM は当人どうしと管理者しか読めません（v73 より前に送った DM は、管理者がアプリを開いたときに自動でそちらへ移ります）。**チームのチャットは、ほかのチームの人も通信を細工すれば読めます**
10. 次のものは、画面では分けていますが、**通信を細工すれば同じ旅行の参加者には読めてしまいます**（集計や表示に使うため）：チーム内のみ・本人のみのポイント履歴、他の人の位置（位置の共有をオンにしている人）、アンケートの回答（「誰が何に入れたかを出さない」にしたものも含む）、入金状況、立て替えの記録、チェックリスト、クイズの解答、チームのチャット、地図の「管理者だけ」のピン、**チーム宛て・個人宛てのお知らせ**。書き換えはできません。**暗証番号のように本人以外に見せたくないものは、お知らせの「人ごと」で送ってください**（こちらは本人と管理者しか読めません）
11. 機能を足して**新しい種類のデータ（コレクション）を作ったときは、`firestore.rules` に追加しないと参加者は読み書きできません**（管理者はできます）。追加したら `tests/rules.test.mjs` にもテストを足して、貼り直してください

## セキュリティの設定（おすすめ・Firebase と Google Cloud の画面で行う）

アプリのコードだけではできない設定です。どれも無料です。

1. **API キーを、このアプリの URL からしか使えないようにする**
   - https://console.cloud.google.com/apis/credentials （プロジェクト `island2027spring` を選ぶ）
   - 「API キー」の `Browser key (auto created by Firebase)` → **アプリケーションの制限**：「ウェブサイト」→ `https://shashikata.github.io/*` を追加 → 保存
   - これで、他のサイトからこのキーを使ってアカウントを作ったりすることができなくなります（ログイン画面のある URL を変えたら追加し直す）
2. **管理者のアカウントが3つとも作られているか確かめる（いちばん大事）**
   - Firebase コンソール →「Authentication」→「ユーザー」に `admin1@` `admin2@` `admin3@island.example.com` が **3つとも** あること
   - 1つでも作っていないと、他人がそのアドレスで先にアカウントを作って管理者になれてしまいます。使わない管理者も、作ってパスワードを長くしておいてください
   - 参加者のアカウントは、作られても旅行に追加しない限り何も読めません
3. **使いすぎの通知**
   - 無料プラン（Spark）のままなら、料金はかかりません（上限に達するとその日は止まるだけ）。Blaze プランにした場合は、Google Cloud の「お支払い」→「予算とアラート」で月 100 円などの予算を作り、メールで知らせるようにしてください
4. **バックアップ**
   - 「設定」→「データを PDF で出力」で、旅行の前後に全部を PDF にして保存しておく（Firestore の自動バックアップは有料プランのみ）
5. **Worker の秘密の値**（push-worker/README.md）
   - `VAPID_PRIVATE_KEY` と `FIREBASE_SERVICE_ACCOUNT` は必ず「シークレット」にする。サービスアカウントの JSON ファイルは、Worker に貼ったら端末から消してよい（必要になったら作り直せる）

アプリ側で行っていること：`index.html` の Content-Security-Policy で、スクリプトを読み込める場所を Firebase・cdnjs・jsDelivr とアプリ自身に限っています（外部のものを足したら、ここにも足してください）。

## テストの方法（開発者向け）

Node.js 18 以上と Java 11 以上が必要です。

```bash
cd tests
npm install
npm test        # firestore.rules のテスト
```

手元で画面を試すとき：`firebase emulators:start --project demo-island --only auth,firestore` を起動しておき、このフォルダで `python3 -m http.server 5173` を実行し、`http://localhost:5173/` を開く。`localhost` で開いたときは、自動的にエミュレーター（本物の Firebase には接続しない）を使います。
