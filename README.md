# 旅行ポータル

管理者がPCやスマホから入力した **お知らせ・チーム発表・ポイント** を、参加者がそれぞれのアカウントでスマホから見られる Web アプリです。

- 画面：GitHub Pages（無料）
- ログインとデータ保存：Firebase（Authentication + Cloud Firestore、無料の Spark プランで足ります）

## できること

| 機能 | 管理者（admin1〜admin3。画面では「管理者1〜3」） | 参加者（user01〜） |
|---|---|---|
| お知らせ | 投稿・削除・固定。宛先を **全員 / 特定チーム / 特定の人** から選べる。画像は3枚まで（自動で縮小） | 自分が見てよいものだけ表示 |
| チーム | **チーム表を複数**作れる（例：チーム表1＝競技、チーム表2＝料理班）。チーム表ごとに作成・振り分け（手動 / ランダム）・**発表** | 発表されたチーム表だけ見える |
| ポイント | 個人用・チーム用を付与・取り消し。1件ごとに **全員に公開 / チーム内のみ / 本人のみ** を選べる | 自分・自分のチーム・公開ランキング。加点・減点はお知らせ欄にも緑 / 赤で流れる |
| ポイント交換 | 個人間・チーム間で「渡す側 −N / 受け取る側 +N」を1組で登録。取り消すと両方戻る | 自分に関係する交換がお知らせ欄に流れる |
| 見ました | お知らせに「見ました」ボタンを付けられる。見た人 / まだの人がわかる | ボタンを押すだけ |
| スパイ | チーム表ごとに「参加先チーム」と「本当のチーム」を登録。チームへのポイントは「誰の功績か」を選べ、スパイの功績は参加先 / 本当のチームのどちらに加算するか選べる | 他の人からは参加先の普通のメンバーに見える。本人にだけ本当のチームが見える |
| 表・メモ | 「全体公開」と「管理者用」の2つの欄に、メモと表（リーグ戦の星取表など）を自由に追加・編集。「〜へ移す」で欄を移せる | 公開された表・メモを見られる |
| 地図 | 右上（スマホは左上）の地図ボタンで現在地を表示。「設定」で参加者への表示をオン / オフ。「参加者の位置を共有」をオンにすると、全員の位置が名前つきで地図に出る（「参加者同士でも見られる」で参加者にも表示） | 管理者がオンにすると地図ボタンが出る。一度見た範囲の地図は電波がなくても表示できる |
| クイズ | 「クイズ」から問題（4択 / 記述 / 早押し）・配点・制限時間・解答者を登録。**表示用**（プロジェクター用、admin1 など）と**操作用**（admin2 など）の画面を別アカウントで開き、出題 → 締切 → 正誤判定 → 発表を操作。発表は「一斉 / 一人ずつ」「回答だけ先に見せる → ○× 」など、その場で選べる。終了時に得点をポイントに反映できる。操作用の画面には**次の問題**も表示。**問題読み**（問題文を1文字ずつ出す画面）を問題ごとに入れられ、早押しは最初から入っている（読み上げ中も押せて、押された所で止まる）。早押しの誤答・時間切れは表示用の画面の「誤答」一覧にすぐ出る | 解答者に選ばれた人のスマホに解答画面が自動で出る。問題文をスマホにも出すかは問題ごとに管理者が決める。早押しは「問題が届いてから押すまでの時間」で順位を付けるので、通信の速さの差は影響しない。押した順に解答権が回り、解答権を得たら6秒以内に答えを入力（間に合わなければ誤答） |
| クイズの妨害・賭け | クイズごとに **妨害システム** と **順位予想（賭け）** をオン・オフ。使うポイントは「個人」か「チーム（チーム表を選ぶ）」。妨害は 封印・時間短縮・目隠し（標準）＋ 出遅れ・シャッフル・逆さま（4択・記述向け、オフで用意）を種類ごとにオン・オフ・値段設定。クイズを **区切り（A問題・B問題…）** に分け、区切りごとに「1人が妨害できる回数」「1人が受ける種類ごとの上限」を決める。賭けは 単勝・2連単・3連単・3連複（パリミュチュエル方式、払戻率・上限を設定）。開始前に **ルール説明スライド** を表示用の画面とスマホに出せる | 解答者以外（設定で全員も可）が、操作用の画面の「妨害受付」中にスマホから相手と種類を選んで申し込む。次の問題が出た瞬間に先着順で確定（1問で1人が受ける妨害は1つまで・失敗はポイントを引かない・同じ人を2問続けて狙うと2倍）。誰が誰を妨害したかは画面に出る。賭けは受付中にオッズを見ながら賭け、結果発表で払い戻し（誰も当たらなければ返金） |
| 地図のピン | 地図の「📍ピン」を押してから地図をタップすると、そこにピンを刺せる（名前・メモ・アイコン・色・「全員に表示 / 管理者だけ」）。ドラッグで移動、タップで編集・削除 | 「全員に表示」のピンだけ見える。タップで名前とメモ |
| 出欠・集金 | 「出欠・集金」から **アンケート**（選択肢・締切・集計を参加者に見せるか・コメント欄・答えてもらう人＝全員 / アカウントから選ぶ）を作り、回答状況と未回答の人を確認。回答を代わりに入れることもできる。**集金**（名前・1人あたりの金額・期限・振込先などのメモ・対象＝全員 / アカウントから選ぶ / アンケートで「参加」と答えた人など）を作り、1人ずつ **未入金 / 入金済み / 免除**・払い方（現金・振込・PayPay）・金額の個別変更を付ける。人ごとの未入金の合計も表示。アンケート・集金とも、**作ったあとで「対象者を変える・追加する」から対象者を足したり外したりできる** | アンケートに回答（締切まで変更可）。自分の集金の金額と入金状況が見える。払ったら **「送金しました」** を押して報告（払い方・メモ・スクリーンショットは任意）。管理者の画面に「確認待ち」として出て、管理者が「入金済みにする」を押すと確定する。未回答・未入金があると上に表示される |
| チャット | 「チャット」から **全体チャット・各チームのチャット・各参加者との1対1（管理者への連絡）** に書き込める。参加者どうしの **DM もすべて見られる**（閲覧のみ）。メッセージの削除もできる | 全体チャット、自分のチーム内チャット、「管理者への連絡」、参加者どうしの DM（「新しいDM」から相手を選ぶ）。未読の数がチャットのボタンに出る |
| 旅行（プロファイル） | 「設定」または上部の旅行名から、中身が空の新しい旅行を何個でも作成・切り替え・削除できる。参加者の ID は旅行をまたいで使い回せる（同じ ID を登録すると既存のアカウントを追加） | 複数の旅行に入っている人は、ログイン後に開く旅行を選ぶ。設定からも切り替えられる |
| 画面 | PC（横幅 1100px 以上）は **お知らせ・チーム・ポイント・表・メモ／参加者を1画面**に並べる。スマホはタブ切り替え | スマホは **1ページ**にまとまり、上部のボタンで移動。右上に **所属チームと所持ポイント** を常時表示 |
| アカウント | 参加者アカウントの一括作成（パスワードは自動生成）。「参加者」→「ID・パスワードを印刷」で **配る用カード**（切り取り線・ログイン用QRコード・使い方つき、A4に10枚）と **一覧表**（管理者の控え）を印刷できる | パスワード変更（変更すると、印刷物には「本人が変更済み」と出る） |
| 電波が弱いとき | 入力は端末に保存され、電波が戻ると自動で送信 | 最後に受信した内容を表示し続ける |

Firebase 側のルール（`firestore.rules`）では「旅行に参加していない人・ログインしていない人はデータを読めない」「参加者は自分の記録（「見ました」・位置・回答など）しか書けない」ことを保証しています（`tests/rules.test.mjs` の26項目のテストで確認）。一方、**参加者どうしの見え方（チーム内のみのポイント、管理者用メモ、クイズの正解など）は画面側で分けています**。通信を細工すれば参加者には読めてしまうので、詳しくは「知っておくべき制限」の10を見てください。

## 準備手順（初回だけ・30分ほど）

> Firebase の画面の表記は変わることがあります。見当たらないときは同じ意味の項目を探してください。

### 1. Firebase プロジェクトを作る
1. https://console.firebase.google.com/ に Google アカウントでログインする
2. 「プロジェクトを作成」を押す。名前は何でもよい（例：`nanuka-island`）。Google アナリティクスは **オフ** でよい

### 2. ログイン機能を有効にする
1. 左メニューの「構築」→「Authentication」→「始める」
2. 「ログイン方法」タブで **メール / パスワード** を有効にして保存する
3. **「ユーザー」タブ →「ユーザーを追加」で、管理者2人を作る（この手順は必ず最初に行うこと）**
   - `admin1@island.example.com`（パスワードは自分で決める）
   - `admin2@island.example.com`
   - `admin3@island.example.com`
   - アプリでは `admin1` / `admin2` / `admin3` と入力すればログインできます（画面上の名前は「管理者1」「管理者2」「管理者3」）

> ⚠️ 管理者アカウントを作る前にアプリの URL を公開すると、他人が先に `admin1` を作って管理者になれてしまいます。必ず先に作ってください。

### 3. データベースを作る
1. 「構築」→「Firestore Database」→「データベースを作成」
2. ロケーションは `asia-northeast1`（東京）または `asia-northeast2`（大阪）を選ぶ。**あとから変更できません**
3. 「本番環境モード」で開始する
4. 「ルール」タブを開き、中身を全部消して、このフォルダの `firestore.rules` の中身を貼り付け、「公開」を押す

### 4. アプリと Firebase をつなぐ
1. 歯車アイコン →「プロジェクトの設定」→ 下の方の「マイアプリ」で `</>`（ウェブ）を押す
2. アプリ名を適当に付けて登録する（Firebase Hosting は **不要**）
3. 表示された `firebaseConfig` の値を `config.js` の `productionConfig` に貼り付ける
4. 必要なら、`config.js` の `APP_TITLE` も書き換える

### 5. GitHub Pages で公開する
1. このフォルダの中身を、GitHub の **public** リポジトリのいちばん上の階層に置く
2. リポジトリの「Settings」→「Pages」→「Build and deployment」で、Source を「Deploy from a branch」、Branch を `main` / `/(root)` にして保存する
3. 1〜2分待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける
4. Firebase に戻り、「Authentication」→「設定」→「承認済みドメイン」に `<ユーザー名>.github.io` を追加する

### 6. 参加者アカウントを作る
1. `admin1` でログインし、「参加者」タブ →「まとめて作成」で `user` `1` 〜 `16` を指定して作成する
2. **表示されたパスワードの一覧を必ずコピーして保存する（あとから再表示できません）**
3. 一覧で表示名（例：たろう）を変更して「保存」を押す
4. 各自に ID とパスワードを渡す（LINE の個別メッセージなど）

### 7. 出発前に必ずやること
- [ ] 全員に一度ログインしてもらい、「ホーム画面に追加」してもらう（アプリのように開け、電波がなくても画面が出る）
- [ ] 機内モードにしてアプリを開き直し、お知らせが表示されることを確認する
- [ ] 管理者2人とも、スマホからポイントを付けられることを確認する
- [ ] チーム表と大事なお知らせは **紙でも1部** 用意する

## 当日の使い方のコツ

- **チーム発表**：「チーム」タブで振り分けを済ませてから「チームを発表する」を押すと、全員の画面に一斉に表示されます。押すまでは参加者からはまったく見えません
- **ポイントの公開範囲**
  - 全員に公開：公開ランキングに反映される
  - チーム内のみ：そのチームのメンバーだけが見られる（相手チームにはわからない）
  - 本人のみ（個人ポイントだけ）：その人だけが見られる
- **間違えたら**：「ポイント」タブの履歴にある「取消」で消せます
- **電波がないとき**：管理者が入力した内容は端末に保存され、電波が戻ったときに自動で送信されます（画面上部に「未送信の変更があります」と出ます）

## 人数・データが増えても重くならないための工夫

参加者20人・お知らせ500件・ポイント履歴3000件で計測しました（PC の Chromium、Firebase エミュレーター）。

| 項目 | 対策前 | 対策後 |
|---|---|---|
| 管理者PCの画面1回の描き直し | 約256ms | 約11ms |
| 参加者スマホの画面1回の描き直し | 約34ms | 約5ms |
| 誰かの位置が届いたときの参加者画面の固まり（10秒間の合計） | 約8.7秒 | 0秒 |
| 参加者の画面の部品数 | 約2,700 | 約600 |

- 長い一覧は最初の20〜50件だけ表示し、「さらに表示」で増やす
- 位置・クイズの更新では、地図・クイズの画面だけを描き直す
- 位置のデータは **地図を開いている間だけ** 受け取る。送る間隔は「30m 以上動いたとき（15秒以上あける）／止まっていても2分に1回」
- 参加者はお知らせ・ポイント履歴を **新しい順に一部だけ** 読み込む（「過去の分を読み込む」で追加）。合計ポイントは `stats/points` に集計して読む。集計は付与・取消のたびに更新し、管理者の端末が全履歴と照らし合わせて、ずれがあれば自動で直す
- Firebase 無料枠（読み取り 5万回/日・書き込み 2万回/日）を使い切ると、その日は（日本時間の夕方まで）アプリが動かなくなるため、読み取り・書き込みの回数を減らすことを優先した

## 知っておくべき制限（正直に書いておきます）

1. **印刷用に、作成したときの初期パスワードを Firebase の `accounts`（管理者だけが読める場所）に控えています。** 参加者からは読めないことをルールのテストで確認済みです。印刷の機能を入れる前に作ったIDは記録がないので、印刷物では空欄（手書き用）になります
1. **参加者がパスワードを忘れたとき、アプリからはリセットできません。** Firebase の無料プランでは、他人のパスワードを変更する仕組みを作れないためです。対策：
   - 管理者はパスワード一覧を必ず保管する
   - 参加者には「パスワードを変更するなら絶対に忘れないこと」と伝える
   - 最終手段：Firebase コンソールでそのユーザーを削除し、アプリで同じ ID を作り直す。**ただし、その人の個人ポイントとチームの所属は引き継がれません**（チーム所属は付け直せます）
2. **アカウントの作成は電波のある場所で行ってください**（オフラインでは作れません）
3. 画像は端末側で縮小して保存しています（1枚あたり最大約180KB、1つのお知らせに3枚まで）。地図などを細かく見せたい場合は、紙も用意してください
4. 参加者の名前は、ログインしている参加者全員から見えます（チーム発表前でも）
5. チーム表を削除しても、そのチームに付けたポイント履歴は残ります（表示は「（チーム）」になります）
6. 地図は OpenStreetMap を使っています。**電波のない島で地図を出すには、出発前に電波のある場所で島のあたりを一度表示しておく**必要があります（拡大率ごとに保存されるので、使いたい拡大率で一度見ておく）。GPS 自体は電波がなくても動きます
7. 位置の共有は、**参加者がアプリを開いている間だけ**届きます（スマホを閉じたり別のアプリを使ったりすると止まる。ブラウザの仕組み上の制限）。最後に届いてから5分以上たった人は灰色で表示されます
8. 送金報告に付けたスクリーンショットは、通信を細工すれば他の参加者にも見えてしまいます（下の10と同じ理由）。口座番号や残高など、見られたくない部分は写さないか、隠してから付けるよう伝えてください
9. チャットは管理者がすべて（参加者どうしの DM も）見られます。**画面には表示しないので、事前に管理者から参加者へ口頭で伝えてください**。また下の10と同じ理由で、通信を細工すれば参加者が他の人の DM を読むこともできてしまいます
10. `firestore.rules` は汎用の形にしてあり、機能を追加しても**貼り直す必要はありません**（管理者はすべて読み書きでき、参加者は自分が入っている旅行のデータを読める＋「uid が自分」のデータだけ書ける）。友達同士で使う前提の作りなので、**通信を細工すれば参加者には次のものも読めてしまいます**：チーム内のみ・本人のみのポイント、管理者用のメモ、スパイの本当のチーム、**クイズの問題と正解**、他の人の位置・アンケートの回答・入金状況。書き換えはできません（入金済みにする、他人の回答を変える、などは不可）

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` / `style.css` / `app.js` | 画面とその動き |
| `config.js` | **ここだけ書き換える**（Firebase の設定、タイトル、管理者ID） |
| `firestore.rules` | 誰が何を読み書きできるかのルール（Firebase に貼り付ける） |
| `sw.js` / `manifest.webmanifest` / `icon*` | オフラインで開くための仕組みとアイコン |
| `firebase.json` / `tests/` | 手元でのテスト用（公開には不要だが、置いておいても害はない） |

## テストの方法（開発者向け）

Node.js 18 以上と Java 11 以上が必要です。

```bash
cd tests
npm install
npm test        # firestore.rules のテスト
```

手元で画面を試すとき：`firebase emulators:start --project demo-island --only auth,firestore` を起動しておき、このフォルダで `python3 -m http.server 5173` を実行し、`http://localhost:5173/` を開く。`localhost` で開いたときは、自動的にエミュレーター（本物の Firebase には接続しない）を使います。
